# dsh-session-pin 安装部署说明

**插件**：`dsh-session-pin` 0.1.0 —— 给 DSH Web 侧栏会话列表加「置顶 / 收藏」
**分发地址**：`$EXCHANGE`（团队内网交换站；公网用户直接用 GitHub Release，见 README。地址由团队内部文档提供，本仓库不硬编码内网地址）
**形态**：DSH bundle（host 半 + 浏览器半 + loader patch），无 npm 依赖（只用 Node 内置模块）

---

## 1. 它做什么

| 位置 | 行为 |
| --- | --- |
| 会话行（鼠标悬停） | 行右侧动作区出现 ★ 按钮，点一下置顶 / 取消 |
| 已置顶的行 | 标题前出现常驻 ★ 徽标 |
| 列表顺序 | 置顶会话升到**所在账户桶**最前（分组视图 = 该 workspace 组内；扁平列表 = 整个列表） |
| 设置 → *Pinned Sessions* | 列出所有置顶，支持逐条取消与「全部取消置顶」 |
| 主机端 | 状态存 `$DSH_HOME/plugin-data/dsh-session-pin/pins.json`，每小时清理已删除会话的置顶 |

排序是**通过 DSH 自带的 `setSessionOrder`** 写入的（与官方拖拽排序同一个状态），不替换任何组件；浏览器另存一份 `localStorage` 镜像，多标签页用 `storage` 事件实时同步。

```
┌ my-workspace ─────────────────────────┐
│ ★ 示例：会话缓存重构          5min    │  ← 置顶：★ 徽标 + 排在组内最前
│   New Session                         │
│   示例：部署抖动排查          15h     │  ← 悬停此行 → 右侧出现 ★ 可点
│   示例：检索参数调优          21h     │
└───────────────────────────────────────┘
```

## 2. 环境要求

| 项 | 要求 |
| --- | --- |
| DSH | 任意带 Web 界面的 profile（默认 `web`），`@deepseek-ai/dsh-base` + `dsh-web-app` 已在 bundles 里 |
| Node | ≥ 18（自测用 `node --test`；跑插件本身只需 DSH 自带运行时） |
| 安装脚本 | `bash` + `curl` + `tar` + `sha256sum` + `python3`（改写 profile 清单用） |
| 网络 | 在线安装需能访问你的分发站（内网交换站或 GitHub）；气隙环境可走发布包内 `install.sh` |

## 3. 安装（推荐：自举脚本）

```bash
# ⓪ 把分发地址设成你们的交换站（公网用户跳过这步，脚本默认走 GitHub Release）
EXCHANGE=http://<你的交换站>/exchange/dsh

# ① 下载脚本
mkdir -p ~/dsh-pin && cd ~/dsh-pin
curl -fsSLO "$EXCHANGE/install-dsh-session-pin.sh"

# ② 先干跑看它要做什么（不改任何文件）
bash install-dsh-session-pin.sh --dry-run

# ③ 正式安装（自动下载发布包 + 校验 sha256 + 装进 web profile）
bash install-dsh-session-pin.sh --profile web

# ④ 重启 DSH，然后验收
curl -s http://127.0.0.1:3080/api/dsh-session-pin/pins     # 期望 {"version":1,"pins":{}}
```

装完脚本会打印源码目录、安装目录、清单备份路径与重启命令。想让它顺手重启，加 `--restart`
（本机有 `~/bin/restart-dsh-web.sh` 就调它，否则用 `systemctl --user restart dsh-web.service`）。

常用开关：

| 开关 | 作用 |
| --- | --- |
| `--profile <名>` | 装进哪个 profile（默认 `web`） |
| `--dsh-home <目录>` | DSH 主目录（默认 `$DSH_HOME` 或 `~/.dsh`） |
| `--dest <目录>` | 源码落地目录（默认 `~/dsh-session-pin`） |
| `--from <目录>` | 用本地已解包目录安装，不下载 |
| `--port <n>` | 验收用端口（默认 3080） |
| `--dry-run` / `--no-test` / `--keep-work` | 只打印动作 / 跳过装后自测 / 保留临时目录 |

## 4. 安装（手动四步，等价于脚本）

```bash
PROFILE_DIR=~/.dsh/profiles/web
SRC=~/dsh-session-pin                      # 解包后的发布包目录

# 1) 放进 profile 的 node_modules（复制，不是软链）
mkdir -p "$PROFILE_DIR/node_modules/dsh-session-pin"
cp -a "$SRC"/{package.json,cordis.patch.yml,lib,README.md,docs} \
      "$PROFILE_DIR/node_modules/dsh-session-pin/"

# 2) 登记为 bundle（dependencies + dsh.profile.bundles 两处都要）
python3 - "$PROFILE_DIR/package.json" "$SRC" <<'PY'
import json, sys, collections
path, src = sys.argv[1], sys.argv[2]
d = json.load(open(path, encoding="utf8"), object_pairs_hook=collections.OrderedDict)
d.setdefault("dependencies", collections.OrderedDict())["dsh-session-pin"] = "file:" + src
b = d.setdefault("dsh", collections.OrderedDict()).setdefault("profile", collections.OrderedDict()).setdefault("bundles", [])
if "dsh-session-pin" not in b:
    b.append("dsh-session-pin")
json.dump(d, open(path, "w", encoding="utf8"), indent=2, ensure_ascii=False)
open(path, "a").write("\n")
print("bundles =", ", ".join(b))
PY

# 3) 重启（bundle 列表只在启动时组装）
systemctl --user restart dsh-web.service     # 或 ~/bin/restart-dsh-web.sh

# 4) 验收
curl -s http://127.0.0.1:3080/api/dsh-session-pin/pins
```

> ⚠️ **不要**再往 profile 自己的 `cordis.patch.yml` 里手写 `id: dsh-session-pin` 的 `insert`。
> 发布包自带的 `cordis.patch.yml` 已经插入该条目，重复会让 DSH 启动失败并报
> `duplicate loader entry id: dsh-session-pin`（这也是本仓库历史上踩过的坑）。

## 6. 卸载

```bash
PROFILE_DIR=~/.dsh/profiles/web
rm -rf "$PROFILE_DIR/node_modules/dsh-session-pin"
python3 - "$PROFILE_DIR/package.json" <<'PY'
import json, sys, collections
p = sys.argv[1]
d = json.load(open(p, encoding="utf8"), object_pairs_hook=collections.OrderedDict)
d.get("dependencies", {}).pop("dsh-session-pin", None)
b = (d.get("dsh", {}).get("profile", {}) or {}).get("bundles")
if isinstance(b, list) and "dsh-session-pin" in b:
    b.remove("dsh-session-pin")
json.dump(d, open(p, "w", encoding="utf8"), indent=2, ensure_ascii=False)
open(p, "a").write("\n")
PY
rm -rf ~/.dsh/plugin-data/dsh-session-pin      # 想连置顶记录一起清掉再加这句
# 重启 DSH 生效
```

## 7. 排障

| 现象 | 原因 / 处理 |
| --- | --- |
| 启动失败：`duplicate loader entry id: dsh-session-pin` | profile 的 `cordis.patch.yml` 与 bundle 各自插入了一次。删掉 profile 里那段 `insert`。 |
| `plugin tree failed to load` | 看启动日志里的插件名；多为 `node_modules/dsh-session-pin` 不完整（缺 `lib/` 或 `package.json` 里没有 `dsh.bundle`）。重新解包覆盖。 |
| API 404 | 没重启（bundle 列表启动时才组装），或 host 半未装载（看启动日志有没有 `[dsh-session-pin]`）。 |
| **星标图标在，点了没反应** | 浏览器还在跑旧 bundle。**强制刷新**（Ctrl/Cmd+Shift+R）。0.1.0 修复了两处真 bug（见下），旧 bundle 的点击会被浏览器吞掉。 |
| 置顶了但没排到最前 | 0.1.0 之前的版本会把顺序写进错的账户桶（未分组桶），需升级到 0.1.0 并强刷。 |
| 改了 `pins.json` 不生效 | host 首次读入后**常驻内存**，外部改文件无效。请用 API（`POST /api/dsh-session-pin/set`）或重启 DSH。 |
| 设置页看不到 *Pinned Sessions* | 浏览器半没装载（同「API 404」），或该 profile 没挂 `dsh-client-ui-settings`。 |
| 装完不知道装哪了 | 脚本会打印三行路径；也可 `ls ~/.dsh/profiles/web/node_modules/dsh-session-pin`。 |

## 8. 文件与路径

| 路径 | 说明 |
| --- | --- |
| `~/.dsh/profiles/<profile>/node_modules/dsh-session-pin/` | 安装位置（DSH 从这里解析 bundle） |
| `~/dsh-session-pin/` | 源码目录（脚本默认落地处，`--dest` 可改） |
| `~/.dsh/profiles/<profile>/package.json` | 已登记 `dependencies` + `dsh.profile.bundles`（装前自动备份 `*.dsh-session-pin.bak-<时间戳>`） |
| `~/.dsh/plugin-data/dsh-session-pin/pins.json` | 置顶状态（`{version, pins:{id:{pinned,pinnedAt}}}`） |
| `/plugins/dsh-session-pin/client.js` | 浏览器半的 HTTP 入口（`cache-control: no-cache`） |
| `/api/dsh-session-pin/{pins,set,prune}` | host 半的 HTTP 面 |

## 9. 0.1.0 修复的两个真 bug（升级理由）

1. **「有图标、点击无反应」**：旧实现用 `btn.innerHTML !== 模板` 判断是否重画，而浏览器把自闭合 `<path/>` 序列化成 `<path></path>`，字符串**永远不相等** → 每轮扫描都重建按钮子树；当重建落在 `mousedown` 与 `mouseup` 之间，浏览器因点击目标不一致而**完全不派发 click**。改为用 `dataset.pinState` 记录已渲染状态，只在真实状态变化时重画。
2. **「置顶不排最前」**：旧实现从行 fiber 上找 `props.group.key`，而行 fiber 上根本没有 `group`（只有 `node`）；账户桶键应取**祖先** order face 上的 `workspaces[].workspaceId`（未分组为 `""`，扁平列表为 `"__flat_session_order__"`）。写错桶 → 顺序不变。

回归测试 `test/smoke.test.mjs` 覆盖这两点（13 项），其中「glyph 不被重画」一项在旧代码上必须为红。
